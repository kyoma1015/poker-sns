# 自律開発・導入ロードマップ

## Phase 1: 基盤（本PR）
- 共通進捗ファイル、担当別進捗ファイル、承認ルール
- pull_request で npm ci / npm run build / npm run lint
- Issue入力テンプレート
- 現時点で自動コード修正、Issue自動割当、Workの自動起動は未実装

## Phase 2: 信頼できるテスト
- A: 通知・認証・RLSに対する副作用なしのモック試験
- B: TDA正解位置、重複、参照条文、表現品質のデータ検査
- C: 独立したGTOエンジンの回帰・性能・精度検証（外部リポジトリ/成果物の所在を確定）
- D: 診断のスコア・境界値・36動物分類・保存可否の検査
- PRでテストを起動し、失敗時は証拠付きで報告

## Phase 3: 実行エージェント（未実装）
- Issueを1件ずつキューイング、担当ブランチを作成
- 信頼済みのAI実行環境で差分生成、テスト、ドラフトPR作成
- 実行回数・トークン・時間・費用上限、重複防止、タイムアウト、再試行を設定
- 実行環境の秘密情報へのアクセスを最小化
- ブランチ保護と必要なレビュー・本番承認を強制

## Phase 4: 統括と報告（未実装）
- GitHub Issue / PR / CI を唯一の進捗根拠として4ラインを集約
- 依存関係、衝突、P0/P1優先順位を管理
- 日次サマリーと承認待ち事項をオーナーへ通知

## 導入前の確認事項
- GTO成果物の実体・ライセンス・計算環境
- テスト用Supabaseの有無とRLSのテスト方式
- GitHub Actionsの利用枠と実行エージェント費用
- Vercelプレビューの認証・外部通信範囲
- ブランチ保護・GitHub Actionsの権限設定
