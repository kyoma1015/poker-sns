# Poker ID | 自律開発エージェント運用ルール

## 許可（担当作業ブランチ限定）
- 既存コードの調査、必要なコード変更、テスト追加、ローカル/CIでの検証
- 専用作業ブランチへのコミット、ドラフトPR作成、進捗ファイル更新
- CIの失敗分析と追加修正。PASS条件が曖昧ならBLOCKED扱い

## 明示承認が必要
- mainへのマージと本番デプロイ
- 本番SupabaseへのDDL/DML・RLS・関数・権限などの変更
- 本番利用者の投稿・通知・DMなどへの書き込み
- 有料サービスや追加課金、秘密鍵の取得・変更、データ削除
- ビジネス上の重要な仕様・価格・公開範囲の変更

## 開発実行原則
- 一度に一つの担当Issueをロックして進める。同一ファイルに対する並行変更を避ける。
- 修正前の症状、再現条件、修正箇所、テスト結果、未検証範囲をPRに残す。
- CIが緑でも実機QAが未実施ならQA PASSとは記載しない。
- ブロック時は原因・必要な権限・次の安全な手段を書き残す。
- シークレットはファイル、Issue、コミット、ログに含めない。
- 実行エージェントは別途導入する。これらの文章を置くだけで自動実行にはならない。
